00071 /*      INTERNAL DOCS
00072  *      PICA makes callbacks into the host through the host procs. The host
00073  *      procs are filled in by the host and passed to Sweet Pea at SPInit().
00074  *
00075  *      hostData - data that is given back to each host proc when Sweet Pea
00076  *              calls it. Sweet Pea does nothing with it itself.
00077  *
00078  *      extAllocate - implementation of the Block Suite's AllocateBlock() routine.
00079  *              It is identical to ANSI C malloc(). It returns a pointer to the
00080  *              beginning of the allocated block or NULL.
00081  *
00082  *      extFree - implementation of the Block Suite's FreeBlock() routine. It is
00083  *              identical to ANSI C free(). Note that you can pass it NULL.
00084  *
00085  *      extReallocate - implementation of the Block Suite's ReallocateBlock()
00086  *              routine. It is identical to ANSI C realloc(). It returns a pointer
00087  *              to the resized block or NULL. Note that you can pass it NULL or a
00088  *              newSize of 0.
00089  *  extSubAllocate, extSubFree, extSubReallocate- alternate memory allocation routines 
00090  *      intAllocate, intFree, intReallocate - routines used by Sweet Pea for
00091  *              its own memory needs. You may want to allocate blocks differently
00092  *              with plug-ins and Sweet Pea. Plug-ins are unbounded in their memory
00093  *              needs, while Sweet Pea's memory usage can be approximated.
00094  *
00095  *      startupNotify - called as each plug-in is started up. This is intended
00096  *              as a way to tell the user what's happening during start up.
00097  *              Note that plug-ins may start up at any time, not just during
00098  *              SPStartupPlugins().
00099  *
00100  *      shutdownNotify - called just before and after each plug-in is shut down.
00101  *              Also intended as a way to let users know what's going on.
00102  *
00103  *      assertTrap - called when a fatal assert is triggered. Sweet Pea does
00104  *              not expect execution to continue after an assert.
00105  *
00106  *      throwTrap - called when an internal error is thrown. This can be used
00107  *              during debugging to catch errors as they happen. It should return
00108  *              to allow Sweet Pea to handle the error.
00109  *
00110  *
00111  *      To aid in getting Sweet Pea up and running quickly, you can set any of
00112  *      these to NULL and Sweet Pea will use a default implementation. However:
00113  *      you cannot mix your implementations of the memory routines with
00114  *      Sweet Pea's defaults.
00115  *
00116  *
00117  *      The string pool functions replace the default routines used internally
00118  *      and exported by the Strings suite.  Because they are exported, the behaviors
00119  *      listed below should be followed.
00120  *
00121  *      allocateStringPool - creates a new string pool instance. The host app and
00122  *              Sweet Pea have a string pool which can be used by a plug-in, or a plug-in
00123  *              can create its own.  See the notes in SPStrngs.h on how the pool is
00124  *              implemented.
00125  *              The function should return kSPNoError if the pool is allocated successfully
00126  *              or kSPOutOfMemoryError if allocation fails.
00127  *
00128  *      freeStringPool - disposes of the string pool and any associated memory.  The
00129  *              function should return kSPNoError
00130  *
00131  *      makeWString - the string pool keeps a list of added strings. When a new string is
00132  *              added with MakeWString(), the routine checks to see if it is already in the
00133  *              pool.  If so, the address of the string instance in the pool is returned.  If
00134  *              not, it will add it to the pool and return the address of the newly
00135  *              created string instance.  The behavior is:
00136  *
00137  *                      if ( string == NULL )
00138  *                                      *wString = NULL;
00139  *                                      returns kSPNoError;
00140  *                      else if ( string in string pool )
00141  *                                      *wString = found string;
00142  *                                      returns kSPNoError;
00143  *                      else add string
00144  *                              if successful
00145  *                                      *wString = new string;
00146  *                                      returns kSPNoError;
00147  *                              else
00148  *                                      *wString = nil
00149  *                                      returns kSPOutOfMemoryError
00150  *
00151  *      appStringPool - if the host application has already allocated a string pool to use,
00152  *              it's reference should be passed here.  If this value is NULL, Sweet Pea will
00153  *              allocate the pool when initialized and dispose of it at termination.
00154  *
00155  *      filterEvent - a function called for each event allowing the host to cancel it.
00156  *              The event type is indicative of what the filter is to do.  A  file validation
00157  *              is called before a directory entry is added to the file list (kAddFile).
00158  *              A plug-in validation before a file is checked for PiPL information (kAddPlugin);
00159  *              the host might examine the file name/type to determine whether it should be added.
00160  *              For these 'add' events the return value is TRUE if the item should be skipped
00161  *              or FALSE if should be should be added. The default filter proc, used (if NULL)
00162  *              is passed, will skip files/folders in ( ).
00163  *              The other event is kSuitesAvailable.  It is called when the last suite adding
00164  *              plug-in (as determined by available PiPL information) has been added.  This is
00165  *              a point at which the host can cancel the startup process; for instance, if the host
00166  *              requires a suite from a plug-in, this is the time to check for it.  If the
00167  *              host returns TRUE, the startup process continues.  If it returns FALSE, the
00168  *              plug-in startup is canceled and the host would likely terminate or startup in
00169  *              an alternate manner.
00170  *
00171  *      overrideAddPlugins - if supplied, SP will call the host to create the runtime
00172  *              plug-in list.  This occurs at SPStartupPlugins().  The function takes no parameters
00173  *              as it is up to the host to determine how to do this.  For instance, the host can do
00174  *              this from cached data or, as SP would, from the file list.  A returned error will
00175  *              stop the plug-in startup process.
00176  *
00177  *      overrideStartup - a function called for each SP2 plug-in before it is sent the
00178  *              startup message.  If the host returns FALSE, SP will startup the plug-in normal.
00179  *              If the host returns true, it is assumed that the host has handled the startup
00180  *              for the plug-in, so SP will not do anything for the plug-in.  This is intended
00181  *              to be used with a plug-in caching scheme.
00182  *              The host would be responsible, for instance, for defining the cacheable
00183  *              information in the PiPL, adding it when the callback is made, and later issuing
00184  *              a startup message when the plug-in is actually needed (e.g. when a menu item
00185  *              is selected.)  Two notes: don't forget to SetPluginStarted(), and make sure
00186  *              to use a string pooled char* to kSPInterfaceCaller and kSPInterfaceStartupSelector.
00187  *
00188  *      resolveLink - Windows only.  If the search for plug-ins is to recurse sub-folders,
00189  *              the host needs to supply this routine.  When a .lnk file is encountered, the
00190  *              resolveLink host callback function will be called and should return a resolved path.
00191  *              This is a host callback due to OLE issues such as initialization, which the SP
00192  *              library does not currently handle.  If it returns an error code, the result will
00193  *              be ignored.
00194  *
00195  *      getPluginAccess - Allows the host to set the plug-in access information.  This would
00196  *              be used if, for instance, the host kept its own plug-in list (ala, Photoshop), but
00197  *              still needed these to be compatible with SPPlugins (e.g. whose accesses are used by ADM)
00198  *
00199  *      memoryIsCritical - Mac only.  Allows the host to indicate that memory is in a critical state
00200  *              (really low, but can't be purged because you are, say, shutdown.)
00201  *              If so and the plug-in load target heap is the app heap, when a plug-in fails to load
00202  *              SP will then try to load the plug-in into the system heap
00203  */
